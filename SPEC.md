# sellat-proof/2 — format specification

Version: `sellat-proof/2` · Status: stable · These rules are frozen: issued
proofs must verify forever. Any change requires a new schema version.

A sellat-proof/2 artifact (`proof.json`) makes one claim:

> The data whose SHA-256 is `content.hash` existed no later than the block
> timestamp of the anchoring transaction(s).

The claim is verifiable with the file, the artifact and access to the public
blockchain — nothing else. No SELLAT service or database is involved.

## 1. Artifact shape

```json
{
  "schema": "sellat-proof/2",
  "proof_id": "<uuid>",
  "content": { "algorithm": "SHA-256", "hash": "<64 lowercase hex>" },
  "leaf": { "formula": "SHA-256('sellat-leaf:v2:' + proof_id + ':' + content.hash)",
            "value": "<64 hex>" },
  "merkle": { "index": 0,
              "path": [ { "position": "left|right", "hash": "<64 hex>" } ],
              "root": "<64 hex>" },
  "anchors": [ { "chain_id": 137, "network": "Polygon Mainnet",
                 "tx_hash": "0x…", "block_number": 0, "block_hash": "0x…",
                 "block_timestamp": "<ISO-8601 UTC>",
                 "payload": "sellat:v2:<merkle.root>" } ],
  "times": { "sellat_received_at": "<ISO-8601 UTC>", "note": "…" }
}
```

## 2. Leaf construction

```
leaf = SHA-256( utf8( "sellat-leaf:v2:" + proof_id + ":" + content.hash ) )
```

hex-encoded, lowercase. Including `proof_id` makes two proofs of identical
bytes distinct leaves, so a Merkle path can never be replayed for a different
proof.

## 3. Merkle tree

- Binary tree over the batch's leaves, in batch order.
- `parent = SHA-256( leftBytes || rightBytes )` where `leftBytes`/`rightBytes`
  are the raw 32-byte nodes (not their hex strings).
- A level with an odd node count promotes the last node unchanged — leaves are
  never duplicated.
- The root of a single-leaf tree is the leaf itself.
- `merkle.path` lists sibling hashes bottom-up. `position` is the side the
  **sibling** occupies: `"left"` ⇒ `parent = H(sibling || current)`,
  `"right"` ⇒ `parent = H(current || sibling)`.

## 4. Anchoring

The batch root is committed to one or more EVM chains as a zero-value
transaction from the anchoring wallet to itself, whose `data` field is the
UTF-8 bytes of:

```
sellat:v2:<merkle.root hex>
```

`anchors[]` records, per chain: the transaction hash, block number, block
hash, and the block's timestamp. **The block timestamp is the independently
provable "existed no later than" time.** `times.sellat_received_at` is
SELLAT's own record time and is intentionally weaker evidence.

## 5. Verification algorithm

1. `SHA-256(file) == content.hash`;
2. recompute the leaf with the §2 formula ⇒ must equal `leaf.value`;
3. fold `merkle.path` from the leaf (§3) ⇒ must equal `merkle.root`;
4. `anchors[i].payload == "sellat:v2:" + merkle.root` for every anchor;
5. for at least one anchor, fetch `tx_hash` from any node of that chain and
   check that the transaction's input data equals `payload` (and, if desired,
   that the block number matches and is final).

Steps 1–4 are offline. Step 5 needs any JSON-RPC endpoint or block explorer —
the verifier never contacts SELLAT.

## 6. What this format does NOT claim

A proof demonstrates **existence and integrity at a point in time** — not
authorship, ownership, authenticity of depicted content, or truth. A file
generated by an AI and anchored a minute later has a perfectly valid proof of
having existed at that minute.
